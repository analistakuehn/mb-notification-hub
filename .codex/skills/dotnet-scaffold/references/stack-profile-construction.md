# Stack Profile Construction

The scaffold builds `.araia/stack-profile.yaml` from resolved arguments and the
selected declarative starter, and writes it only after locked restore, build,
and tests pass. Brownfield inspection detects the same schema from source and
records any other architecture values it finds.

Schema and consumer contract:
[`../../../references/stack-profile-protocol.md`](../../../references/stack-profile-protocol.md).

## Axes

| Axis | Greenfield value or source |
|---|---|
| `target-framework` | `--framework`, currently `net10.0` |
| `lang-version` | `latest` |
| `nullable` and `implicit-usings` | `enable` |
| `namespace-strategy` | `prefixed`, with `root-namespace-prefix: <Namespace>` |
| `central-package-management` | `true` |
| `architecture` | the selected entry's canonical architecture |
| `mediator` | `none` |
| `validation` | `fluent-validation` |
| `error-handling` | `result-pattern` |
| test dialect | `xunit`, `nsubstitute`, `shouldly`, and `bogus` |
| `arch-tests` | `netarchtest` |
| `http-mocking` | `mvc-testing` |
| feature axes | resolved CLI selections |
| `messaging-consumer-pattern` | `raw` when messaging is selected, otherwise `none` |
| `resilience` | `http-resilience` |
| `serialization` | `system-text-json` |
| `telemetry` | `none` until actual wiring exists |
| `auth` | `none` until a production authentication scheme exists; the host still ships fail-closed authorization defaults |
| `distributed-locks` | `none` |
| `slice-layout.file-naming` | `dot-suffix` |

## Topology-dependent axes

`architecture`, `features-root`, and `slice-shape` come from the selected
starter manifest, so a consumer can locate slices without knowing the catalog:

| Entry | `architecture` | `slice-layout.features-root` | `slice-layout.slice-shape` |
|---|---|---|---|
| `modular-monolith` | `modular-monolith` | `src/Platform.Api/Modules` | `module-with-vertical-slices` |
| `vertical-slice` | `modular-monolith` | `src/Platform.Api/Modules` | `module-with-vertical-slices` |
| `clean` | `clean` | `src/Platform.Application/Modules` | `layered-with-vertical-slices` |
| `hexagonal` | `hexagonal` | `src/Platform.Core.Application/Modules` | `ports-and-adapters-with-vertical-slices` |

`starter` is deliberately not a Stack Profile axis. `modular-monolith` and
`vertical-slice` resolve to the same observable macro architecture, so the
profile records the architecture and leaves selection provenance to the
generator JSON and `.araia/scaffold-metadata.json`.

## Honesty rule

The profile records observable generated capabilities, never intent. Do not
claim an outbox, an inbox, telemetry, production authentication, distributed
locks, or runtime-AI guardrails because the architecture recommends them. Those
axes stay `none` until the corresponding mechanism exists and is verified.

## Header and guard

```yaml
# Generated by dotnet-scaffold on <ISO-8601 UTC>.
# Override values by editing this file; add `# manually-edited: true` before running the analyzer.
```

Without `--force`, a manually edited profile blocks regeneration. The scaffold
treats identical profile bodies as unchanged even when generation timestamps
differ, so a rerun stays idempotent.

When the schema changes, update the protocol first and keep greenfield
construction and brownfield detection compatible. Adding a topology means adding
a row to the table above, not a new axis.
