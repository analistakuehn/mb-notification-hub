# Runtime and Performance Evidence Scope

Loaded on demand by `dotnet-runtime-diagnostics` and the read-only `dotnet-specialist`.

Assess: **Allocation patterns** (object creation in hot paths, closure/delegate allocations, boxing); **Caching strategies** (static vs instance, invalidation, lifetime safety); **Async overhead** (unnecessary state machines, `ValueTask` vs `Task`); **LINQ in hot paths** (manual iteration to avoid allocations); **String ops** (concatenation/interpolation/StringBuilder in loops); **Collections** (array vs List vs Span, pre-sizing); **Lock-free patterns** (`ConcurrentDictionary`, `Interlocked`, `volatile`); **Producer/consumer (Channels)** (bounded vs unbounded choice, `BoundedChannelFullMode` chosen per semantics, `SingleReader`/`SingleWriter` flags reflect actual usage, fan-out/fan-in composition, `Parallel.ForEachAsync` over `ChannelReader<T>.ReadAllAsync` for stage concurrency, no `BlockingCollection<T>` in async code); **Dataflow graphs** (per-block `BoundedCapacity` and `MaxDegreeOfParallelism`, `LinkTo` with `PropagateCompletion`, `EnsureOrdered` choice, batching and joining, justified vs Channels for the same problem); **Byte-stream pipelines** (`PipeReader`/`PipeWriter` over `Stream`+`MemoryStream` on hot I/O paths, `ReadOnlySequence<byte>` with `SequenceReader<byte>` for parsing without copy, correct `AdvanceTo(consumed, examined)` discipline); **Async streaming** (`IAsyncEnumerable<T>` with `[EnumeratorCancellation]` and `WithCancellation`/`ConfigureAwait(false)`, no `.ToListAsync()` materialization on the hot path); **Benchmark presence** (BenchmarkDotNet project? covers critical paths? uses `MemoryDiagnoser`?); **GC pressure** (LOH, pinning, finalizers).

Not in scope: SOLID/design patterns (`dotnet-architect`); C# idioms, DI lifetimes, DDD, and build governance (`dotnet-specialist`); naming, function design, code smells, and test quality (`dotnet-engineer`).
