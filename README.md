# MonteBravo.NotificationHub

Pragmatic Modular Architecture .NET foundation generated by `dotnet-scaffold`.

## Architecture

| Path | Responsibility |
|---|---|
| `src/Platform.Api/` | host |
| `tests/Platform.ArchTests/` | arch tests |
| `tests/Platform.SecurityArchTests/` | security arch tests |
| `tests/Platform.UnitTests/` | unit tests |
| `tests/Platform.IntegrationTests/` | integration tests |
| `tests/Platform.PerformanceTests/` | performance benchmarks |

The initial bounded context is `TemplateManagement`. Its context home is `src/Platform.Api/Modules/TemplateManagement/`.

Each bounded context owns its domain model, its vertical slices, its versioned public contracts, and its technology. Keep a feature's command, validator, handler, source-generated logger, response, and transport mapping together. Domain code must not depend on infrastructure, and one context must never reach into another context's infrastructure. `docs/architecture/standards/modular-monolith-architecture.md` records the enforced dependency rules for this topology.

Interfaces represent demonstrated external boundaries. Repositories and domain policies remain concrete unless observed pain justifies an abstraction. When cross-context asynchronous delivery is implemented, use distinct, versioned Integration Event contracts and add a transactional outbox plus an idempotent inbox before relying on delivery guarantees; those mechanisms are not generated by this scaffold.

## Test

```bash
dotnet test
```

Commit `packages.lock.json` after the first verified restore. The generator performs a locked restore, builds with warnings as errors, and runs the deterministic tests locally. Add equivalent CI gates and package vulnerability/deprecation checks before production promotion; this scaffold does not create a CI workflow.

## Selected features

### Minimal API transport

- Endpoint filters live under `src/Platform.Api/Infrastructure/EndpointFilters/`.
- Wire validation and logging onto an endpoint with the extension methods:

  ```csharp
  app.MapPost("/customers", RegisterCustomerEndpoint.HandleAsync)
     .WithValidation<RegisterCustomer.Command>()
     .WithRequestLogging()
     .RequireAuthorization("Customers.Register")
     .RequireRateLimiting("customers-write");
  ```

- OpenAPI is exposed at `/openapi/v1.json` via `Microsoft.AspNetCore.OpenApi`.

### EF Core persistence

Configure `Modules:TemplateManagement:Persistence:Ef:ConnectionString` with user
secrets or the production secret provider. The committed loopback value has
no password. The default scaffold targets Npgsql; swap to SQL Server by replacing
`UseNpgsql` with `UseSqlServer` in `EfSetup.ConfigureDbContextOptions` and
updating `Directory.Packages.props`.

### Migrations

```bash
dotnet ef migrations add Initial --context TemplateManagementDbContext --project src/Platform.Api --startup-project src/Platform.Api
dotnet ef database update --context TemplateManagementDbContext --project src/Platform.Api --startup-project src/Platform.Api
```

Handlers may use `TemplateManagementDbContext` directly for simple aggregate-scoped
work. Introduce a concrete repository only when it hides real query or
persistence complexity. Read paths use `AsNoTracking` plus DTO projection;
mutable aggregate roots use optimistic concurrency.

### Redis cache

Configure under `Modules:TemplateManagement:Cache:Redis`. Keep credentials in user
secrets or the production secret provider. The scaffold registers:

- `IConnectionMultiplexer` (singleton) for raw Redis access
- `IDistributedCache` backed by Redis for ASP.NET Core caching APIs

Inject either one in slice repositories. When the `hybrid-cache` feature is
also selected, `HybridCache` automatically uses Redis as the L2 store.
