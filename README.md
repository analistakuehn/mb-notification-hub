# MonteBravo.NotificationHub

Pragmatic Modular Architecture .NET foundation generated by `dotnet-scaffold`.

## Architecture

| Path | Responsibility |
|---|---|
| `src/Platform.Api/` | host |
| `tests/Platform.ArchTests/` | arch tests |
| `tests/Platform.SecurityArchTests/` | security arch tests |
| `tests/Platform.UnitTests/` | unit tests |
| `tests/Platform.IntegrationTests/` | integration tests |
| `tests/Platform.PerformanceTests/` | performance benchmarks |

The initial bounded context is `TemplateManagement`. Its context home is `src/Platform.Api/Modules/TemplateManagement/`.

Each bounded context owns its domain model, its vertical slices, its versioned public contracts, and its technology. Keep a feature's command, validator, handler, source-generated logger, response, and transport mapping together. Domain code must not depend on infrastructure, and one context must never reach into another context's infrastructure. `docs/architecture/standards/modular-monolith-architecture.md` records the enforced dependency rules for this topology.

Interfaces represent demonstrated external boundaries. Repositories and domain policies remain concrete unless observed pain justifies an abstraction. When cross-context asynchronous delivery is implemented, use distinct, versioned Integration Event contracts and add a transactional outbox plus an idempotent inbox before relying on delivery guarantees; those mechanisms are not generated by this scaffold.

## Desenvolvimento com Docker

Pré-requisito: Docker Desktop em execução.

Suba a API, o worker de relay e as dependências locais:

```bash
docker compose up --build
```

O Compose também sobe o worker `dispatcher`, que consome as filas de e-mail,
SMS e push. O arquivo `.env` local aponta para o diretório de User Secrets do
projeto; ele é ignorado pelo Git e o volume é montado somente como leitura nos
hosts que podem enviar notificações.

Serviços publicados no host:

| Serviço | Endereço | Uso |
|---|---|---|
| API | `http://localhost:8080` | HTTP, health check e OpenAPI |
| PostgreSQL | `localhost:5432` | Persistência local |
| Redis | `localhost:6379` | Cache e controles efêmeros |
| LocalStack | `http://localhost:4566` | SQS e S3 locais |

### Teste de e-mail e SMS

As credenciais locais do SendGrid e do Twilio foram migradas para o User Secrets
do `Platform.Api`. O segredo original não deve ser copiado para
`appsettings*.json`, `.env` ou qualquer arquivo versionado. Para conferir apenas
os nomes configurados:

```bash
dotnet user-secrets list --project src/Platform.Api
```

O SendGrid permanece em modo sandbox. O Twilio usa o produto e o modo de
autenticação encontrados no projeto de origem. O modo `Verify` espera que o
corpo do SMS seja um código de 4 a 10 caracteres; para mensagens livres, troque
o segredo `Modules:Dispatch:Providers:Twilio:Product` para
`ProgrammableMessaging` e configure `FromNumber` no User Secrets.

O smoke test real usa os adapters do próprio módulo `Dispatch`, desativa o
sandbox do SendGrid somente durante a execução e permanece ignorado na suíte
normal. Execute-o explicitamente no PowerShell:

```powershell
$env:NOTIFICATION_HUB_LIVE_PROVIDER_TESTS = "1"
$env:NOTIFICATION_HUB_LIVE_EMAIL = "destinatario@example.com"
$env:NOTIFICATION_HUB_LIVE_SMS = "+5511999999999"
dotnet test tests/Platform.IntegrationTests/Platform.IntegrationTests.csproj --filter FullyQualifiedName~LiveProviderSmokeTests
```

O SMS enviado pelo smoke test usa o código de verificação `482731`.

Depois de aplicar as migrações, habilite explicitamente os adapters no banco de
desenvolvimento. Isso evita que uma notificação pendente seja enviada durante a
configuração:

```bash
docker compose exec postgres psql -U postgres -d notificationhub -c "INSERT INTO dispatch.provider_config (channel, provider_key, priority, updated_at) VALUES ('email', 'sendgrid', 0, now()), ('sms', 'twilio', 0, now()) ON CONFLICT (channel, provider_key) DO UPDATE SET priority = EXCLUDED.priority, updated_at = EXCLUDED.updated_at;"
```

Para desativar os envios sem apagar a configuração do provedor:

```bash
docker compose exec postgres psql -U postgres -d notificationhub -c "DELETE FROM dispatch.provider_config WHERE channel IN ('email', 'sms');"
```

Verifique o estado e a saúde da API:

```bash
docker compose ps
curl http://localhost:8080/health
```

A especificação OpenAPI fica em `http://localhost:8080/openapi/v1.json` e
continua sujeita à autenticação padrão da API.

O PostgreSQL usa `postgres` como usuário e senha, e o banco `notificationhub`.
Esses valores, assim como as credenciais `test/test` do LocalStack, são somente
para desenvolvimento local.

As migrações não são executadas automaticamente pelo Compose. Com os serviços
de infraestrutura em execução, aplique-as pela máquina hospedeira conforme os
contextos disponíveis:

```bash
dotnet ef database update --context PlatformMessagingDbContext --connection "Host=localhost;Port=5432;Database=notificationhub;Username=postgres;Password=postgres" --project src/Platform.Api --startup-project src/Platform.Api
dotnet ef database update --context TemplateManagementDbContext --connection "Host=localhost;Port=5432;Database=notificationhub;Username=postgres;Password=postgres" --project src/Platform.Api --startup-project src/Platform.Api
dotnet ef database update --context NotificationsDbContext --connection "Host=localhost;Port=5432;Database=notificationhub;Username=postgres;Password=postgres" --project src/Platform.Api --startup-project src/Platform.Api
dotnet ef database update --context ContactConsentDbContext --connection "Host=localhost;Port=5432;Database=notificationhub;Username=postgres;Password=postgres" --project src/Platform.Api --startup-project src/Platform.Api
dotnet ef database update --context DispatchDbContext --connection "Host=localhost;Port=5432;Database=notificationhub;Username=postgres;Password=postgres" --project src/Platform.Api --startup-project src/Platform.Api
dotnet ef database update --context AuditDbContext --connection "Host=localhost;Port=5432;Database=notificationhub;Username=postgres;Password=postgres" --project src/Platform.Api --startup-project src/Platform.Api
```

Para parar os containers, preserve os dados locais com:

```bash
docker compose down
```

Para remover também os volumes locais, use `docker compose down -v`. Essa
operação apaga os dados do PostgreSQL e do Redis deste ambiente.

## Selected features

### Minimal API transport

- Endpoint filters live under `src/Platform.Api/Infrastructure/EndpointFilters/`.
- Wire validation and logging onto an endpoint with the extension methods:

  ```csharp
  app.MapPost("/customers", RegisterCustomerEndpoint.HandleAsync)
     .WithValidation<RegisterCustomer.Command>()
     .WithRequestLogging()
     .RequireAuthorization("Customers.Register")
     .RequireRateLimiting("customers-write");
  ```

- OpenAPI is exposed at `/openapi/v1.json` via `Microsoft.AspNetCore.OpenApi`.

### EF Core persistence

Configure `Modules:TemplateManagement:Persistence:Ef:ConnectionString` with user
secrets or the production secret provider. The committed loopback value has
no password. The default scaffold targets Npgsql; swap to SQL Server by replacing
`UseNpgsql` with `UseSqlServer` in `EfSetup.ConfigureDbContextOptions` and
updating `Directory.Packages.props`.

### Migrations

```bash
dotnet ef migrations add Initial --context TemplateManagementDbContext --project src/Platform.Api --startup-project src/Platform.Api
dotnet ef database update --context TemplateManagementDbContext --project src/Platform.Api --startup-project src/Platform.Api
```

Handlers may use `TemplateManagementDbContext` directly for simple aggregate-scoped
work. Introduce a concrete repository only when it hides real query or
persistence complexity. Read paths use `AsNoTracking` plus DTO projection;
mutable aggregate roots use optimistic concurrency.

### Redis cache

Configure under `Modules:TemplateManagement:Cache:Redis`. Keep credentials in user
secrets or the production secret provider. The scaffold registers:

- `IConnectionMultiplexer` (singleton) for raw Redis access
- `IDistributedCache` backed by Redis for ASP.NET Core caching APIs

Inject either one in slice repositories. When the `hybrid-cache` feature is
also selected, `HybridCache` automatically uses Redis as the L2 store.
